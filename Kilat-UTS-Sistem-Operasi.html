Sistem Operasi

Perangkat lunak sistem yang mengelola resource hardware dan software serta menyediakan interface bagi pengguna.

Kernel = inti OS yang berhubungan langsung dengan hardware, bukan seluruh OS.

Tujuan: interaksi manusia–mesin, efisiensi resource, multitasking dan keamanan.

8 komponen OS

Process · Memory · File System · I/O · Secondary Storage · Networking · Protection & Security · Command Interpreter (UI).

Sejarah

G1 Vacuum tube, belum ada OS
G2 Transistor, Batch
G3 IC, Multiprogramming, Timesharing, UNIX
G4 LSI, PC, Windows/Linux/Mac

Program vs Proses

Program = pasif (file di storage). Proses = program yang sedang dieksekusi. Proses terdiri dari Code, Data, Stack, Heap, PCB.

Status proses

NEW → READY → RUNNING → TERMINATED.
RUNNING → WAITING → READY.
RUNNING → READY (quantum habis / diserobot).

Ready menunggu CPU. Waiting menunggu I/O atau event.

PCB = KTP proses

Pointer · Process State · PID · Program Counter · Registers · Memory Limits · Open Files.

3 Scheduler

Long-term: job → ready queue (paling lambat).
Short-term: ready queue → CPU (paling cepat).
Medium-term: swap RAM ↔ disk.

Scheduler memilih. Dispatcher menyerahkan CPU.

Deadlock

Proses saling menunggu resource yang dipegang yang lain. 4 penanganan: Prevention, Avoidance, Detection, Recovery.

WT = TT − BT

Kalimat sebelum masuk ruang ujian

OS adalah bos komputer. Proses adalah program yang sedang berjalan. PCB adalah KTP proses. Ready menunggu CPU, Waiting menunggu I/O. Scheduler memilih, dispatcher menyerahkan CPU. Angka prioritas kecil berarti lebih penting. TT = Finish − Arrival, WT = TT − BT. Internal = di dalam blok, external = lubang di luar. Virtual address diterjemahkan MMU menjadi physical address.

Pertemuan 1

Apa itu Sistem Operasi

Satu kalimat definisi, tiga tujuan, delapan komponen, dan satu istilah yang sering tertukar: kernel.

Bahasa bayi

Komputer itu kantor besar. Kamu bos yang memberi perintah, OS manajernya, dan hardware adalah barang-barang kantor. Manajer inilah yang memastikan pekerja (CPU) tidak menganggur dan meja kerja (RAM) tidak diperebutkan.

Tulis di jawaban

Sistem Operasi adalah perangkat lunak sistem yang mengelola sumber daya hardware dan software serta menyediakan antarmuka bagi pengguna untuk berinteraksi dengan komputer.

Kata kunci yang harus muncul: mengelola resource dan menyediakan interface.

Tiga tujuan OS

1 · Interaksi

Memudahkan manusia–mesin

Kamu klik Chrome, OS yang mengurus bagaimana Chrome dimuat dan dijalankan. Kamu tidak perlu bicara langsung dengan hardware.

2 · Efisiensi

Memakai resource sebaik mungkin

OS memutuskan CPU dipakai siapa dulu, RAM diberikan ke siapa, file disimpan di mana.

3 · Multitasking & keamanan

Banyak program, aman

Spotify, Chrome, VS Code, dan WhatsApp tampak berjalan bersamaan, tetapi tidak boleh saling merusak.

Kernel

Kernel adalah inti OS yang berinteraksi langsung dengan hardware. Tugas utamanya: manajemen proses, manajemen memori, manajemen I/O, dan proteksi dasar.

Jebakan

"Kernel adalah seluruh sistem operasi." Salah. Kernel hanyalah inti. Antarmuka (shell, GUI) dan utilitas ikut dalam OS, tetapi bukan kernel.

Tambahan mentor, di luar slide

Dua peran OS. OS adalah resource manager (membagi CPU, RAM, disk secara adil dan aman) sekaligus abstraksi (menyembunyikan kerumitan hardware. Kamu menulis "buka file", bukan "geser kepala disk ke sektor 4821").

User mode vs kernel mode. Aplikasi berjalan di user mode dan tidak boleh menyentuh hardware langsung. Kalau butuh (misal membaca file), ia meminta kernel lewat system call. Kernel berjalan di kernel mode yang punya hak penuh. Aturan ini yang membuat satu aplikasi yang error tidak menjatuhkan seluruh komputer. Di Bab 5 kamu akan menemukan bahwa dispatcher bertugas "masuk ke user mode". Itulah kaitannya.

Pertemuan 2

Jenis OS dan sejarahnya

Enam jenis OS dan empat generasi. Sejarah paling mudah dihafal kalau kamu melihatnya sebagai rantai masalah dan solusi.

Enam jenis OS

Batch

Dikumpulkan lalu dikerjakan berurutan

Pengguna tidak berinteraksi langsung. Contoh: pengolahan laporan bank.

Time-sharing

Berbagi waktu CPU

"Kamu 10 ms, kamu 10 ms, kamu 10 ms…" Pergantian begitu cepat sehingga semua terasa berjalan serentak.

Distributed

Banyak komputer, tampak satu sistem

Beberapa komputer bekerja bersama dan pengguna melihatnya sebagai satu sistem.

Network

Mengelola resource jaringan

File sharing, printer bersama, keamanan, akses jarak jauh.

Real-time

Tepat waktu itu wajib

Hard: deadline harus dipenuhi (pesawat, alat pacu jantung). Soft: deadline penting, telat sedikit masih ditoleransi.

Mobile

Untuk smartphone dan tablet

Android, iOS.

Tambahan mentor, di luar slide

Real-time bukan berarti paling cepat. Ia berarti dijamin tepat waktu. Contoh soft real-time: streaming video (telat sedikit hanya menyentak).

Multiprogramming vs time-sharing. Multiprogramming: beberapa program ada di memori, CPU pindah saat satu program menunggu I/O, tujuannya CPU tidak menganggur. Time-sharing: pindah berdasarkan jatah waktu, tujuannya respons cepat untuk banyak pengguna. Time-sharing adalah kelanjutan dari multiprogramming.

Empat generasi sebagai rantai solusi

1940–1950-an
Generasi 1 · Vacuum Tube

Belum ada OS. Programmer menulis bahasa mesin, mengatur kabel, dan memakai punched card. Contoh: ENIAC.

Masalah: semuanya manual dan lambat.

1955–1965
Generasi 2 · Transistor + Batch

Komputer lebih kecil, cepat, murah, andal. Muncul batch processing. Bahasa: FORTRAN dan Assembly.

Masalah: CPU sering menganggur saat program menunggu I/O.

1965–1980
Generasi 3 · IC + Multiprogramming + Timesharing + UNIX

Beberapa program dimasukkan ke memori. Saat A menunggu I/O, CPU mengerjakan B. Berkembang menjadi time-sharing: banyak pengguna berbagi CPU.

Masalah: komputer masih mahal dan besar.

1980–sekarang
Generasi 4 · LSI + Personal Computer

IBM PC, MS-DOS, Windows, Linux, Mac OS, dan OS mobile.

Tulis di jawaban

Perkembangan teknologi G1 → G4: Vacuum Tube → Transistor → IC → LSI/PC.

Pertemuan 3

Konsep dasar proses

Beda program dan proses, isi sebuah proses, stack versus heap, dan lima status proses. Bagian status hampir pasti keluar.

Program

Resep makanan

Kumpulan instruksi yang pasif. chrome.exe yang tersimpan di storage belum melakukan apa-apa.

Proses

Resep yang sedang dimasak

Program yang sedang dieksekusi dan aktif. Saat kamu membuka Chrome, programnya menjadi proses.

Tambahan mentor, di luar slide

Fungsi rekursif tanpa kondisi berhenti terus menambah isi stack sampai penuh. Itulah stack overflow. Di heap, lupa melepas memori yang sudah tidak dipakai disebut memory leak.

Lima status proses, bisa diklik

Tekan tombol kejadian di bawah dan lihat proses berpindah status. Coba tekan kejadian yang tidak mungkin, misalnya "I/O selesai" saat RUNNING. Justru di situlah jebakan ujian bersembunyi.

NEW

"Hai, aku baru lahir." Proses baru dibuat.

READY

"Aku siap, tapi belum dapat CPU." Menunggu giliran di ready queue.

RUNNING

"Sekarang aku kerja!" Sedang memakai CPU.

WAITING / BLOCKED

Menunggu sesuatu selain CPU: I/O, event, atau resource.

TERMINATED

"Pekerjaanku selesai, aku pulang."

Ready ≠ Waiting

Ready menunggu CPU. Waiting menunggu I/O atau event. Ini jebakan nomor satu.

Dua hal yang sering salah

1. Tidak ada panah WAITING → RUNNING. Setelah I/O selesai, proses harus kembali antre di READY.

2. Di rangkumanmu belum ada panah RUNNING → READY. Panah itu ada karena Round Robin dan prioritas preemptive: jatah waktu habis atau ada proses lebih penting, jadi proses diserobot dan kembali ke antrean.

Deadlock

Bahasa bayi

Dua orang saling menunggu dan tak ada yang mau mengalah. Contoh dari slide: P1 memegang printer dan minta tape drive. P2 memegang tape drive dan minta printer. P1 menunggu P2, P2 menunggu P1, selamanya.

Prevention

Jangan sampai terjadi.

Avoidance

Hindari kondisi berbahaya.

Detection

Cek apakah sudah terjadi.

Recovery

Bereskan setelah terjadi.

Tambahan mentor, di luar slide

Empat syarat deadlock (harus terpenuhi semuanya): Mutual exclusion (resource hanya bisa dipakai satu proses), Hold and wait (memegang satu sambil meminta yang lain), No preemption (resource tidak bisa dirampas paksa), Circular wait (ada lingkaran saling menunggu). Singkatan: MHNC.

Prevention bekerja dengan mematahkan salah satu dari empat syarat itu. Detection biasanya mencari siklus pada graf tunggu. Recovery biasanya dengan menghentikan proses atau mengambil paksa resource.

Penjadwalan CPU

Bagian yang paling sering berbentuk hitungan. Pahami tiga hal: siapa dipilih, boleh dipotong atau tidak, dan cara mengisi tabel WT dan TT.

Preemptive vs non-preemptive

Non-preemptive

"Sudah dapat CPU, selesaikan dulu."

Proses tidak boleh direbut. Ia berhenti hanya saat selesai atau masuk waiting. Seperti kamu makan di warung dan orang lain minta gantian: "Tunggu saya selesai."

Preemptive

"Sudah dapat CPU, masih bisa disela."

OS boleh merebut CPU. P1 berjalan, P2 datang dengan prioritas lebih tinggi (atau sisa waktu lebih pendek), maka P1 minggir.

Tambahan mentor, di luar slide

Keputusan penjadwalan terjadi di empat momen: (1) proses berpindah RUNNING → WAITING, (2) RUNNING → READY, (3) WAITING → READY, (4) proses selesai. Sistem non-preemptive hanya menjadwalkan di momen 1 dan 4. Sistem preemptive juga di momen 2 dan 3. Ini menjelaskan mengapa panah RUNNING → READY hanya ada pada algoritma preemptive.

Scheduler

"Oke P2, CPU buat kamu." Tugasnya: context switching, masuk user mode, melompat ke lokasi program yang benar. Waktu yang dibutuhkan = dispatch latency.

Rumus yang wajib hafal

TT = Finish − Arrival
WT = TT − BT = Finish − Arrival − Burst   (aman untuk semua algoritma)
WT = Start − Arrival   (hanya jika proses tidak pernah dipotong)
AWT = ΣWT / n    ATT = ΣTT / n    RT = Start pertama − Arrival
Jebakan

Memakai WT = Start − Arrival pada SRTF atau Round Robin. Proses yang dipotong mulai dari Start, tetapi masih menunggu lagi setelahnya. Untuk jenis preemptive, selalu pakai WT = TT − BT.

Contoh paling gampang

P2 datang di detik 2 tetapi baru dapat CPU di detik 5, jadi menunggu 3. Cek: TT = 8 − 2 = 6, WT = 6 − 3 = 3.

Lima algoritma, masing-masing dengan contoh yang dihitung

FCFS dan convoy effect

Yang datang dulu dilayani dulu. Murah dan sederhana, tetapi satu proses panjang di depan membuat semua yang pendek menunggu lama.

Jika urutannya dibalik jadi yang pendek dulu (itulah SJF), hasilnya jauh lebih baik:

Bahasa bayi

Kamu antre di kasir membawa satu barang, tetapi orang di depanmu membawa satu troli penuh. Itulah convoy effect.

SJF non-preemptive dengan arrival time berbeda

Jangan mengurutkan semua proses berdasarkan BT. Di setiap saat, pilih BT terkecil di antara proses yang sudah datang.

Tambahan mentor, di luar slide

SJF terbukti memberi AWT minimum untuk sekumpulan proses yang burst-nya diketahui. Kelemahannya dua: burst time sebenarnya tidak diketahui di muka (hanya bisa diprediksi, lihat exponential averaging di bawah), dan proses panjang bisa terus tersingkir (starvation).

SRTF: SJF versi preemptive

Setiap kali ada proses baru datang, bandingkan sisa waktu proses yang sedang berjalan dengan BT proses baru itu. Pilih yang terkecil.

Perhatikan P1: di detik 1 sisanya 7, sedangkan P2 yang baru datang hanya butuh 4. P1 minggir. P1 baru lanjut di detik 10 setelah P2 dan P4 selesai.

Round Robin dan quantum

Tiap proses memakai CPU maksimal satu quantum. Kalau belum selesai, ia pindah ke belakang antrean.

Tambahan mentor, di luar slide

Memilih quantum. Quantum sangat besar membuat RR berperilaku seperti FCFS. Quantum sangat kecil membuat respons cepat, tetapi context switch terlalu sering sehingga CPU sibuk berpindah. Dengan n proses dan quantum q, tidak ada proses yang menunggu giliran lebih dari (n − 1) × q.

Kebiasaan soal. Jika ada proses yang datang tepat saat quantum proses lain habis, kebanyakan buku menaruh proses baru lebih dulu di antrean sebelum proses yang baru dipotong. Jika soal atau dosenmu memakai urutan lain, ikuti dosen.

Priority

Setiap proses punya angka prioritas. Menurut materi dosen, angka lebih kecil = prioritas lebih tinggi.

Versi preemptive: proses baru berprioritas lebih tinggi langsung memotong proses yang berjalan.

Tambahan mentor, di luar slide

Priority bisa menyebabkan starvation: proses berprioritas rendah tidak pernah kebagian CPU. Obatnya aging, yaitu menaikkan prioritas proses yang terlalu lama menunggu.

Exponential averaging: memprediksi burst time

SJF perlu tahu burst berikutnya, padahal itu belum diketahui. Solusinya menebak dari riwayat:

τn+1 = α · tn + (1 − α) · τn

tn = burst sebenarnya yang baru terjadi, τn = prediksi sebelumnya, α = faktor penghalus (0 sampai 1, umumnya 0,5). Bahasa bayi: prediksi baru = sebagian data baru + sebagian prediksi lama.

Kasus tepi: α = 0 berarti hanya percaya prediksi lama (riwayat). α = 1 berarti hanya percaya burst terakhir.

Contiguous vs non-contiguous

Contiguous

Satu blok utuh

Proses 10 MB harus mendapat satu ruang 10 MB yang bersebelahan. Dua ruang 5 MB yang terpisah tidak boleh.

Fixed partition: memori dibagi partisi ukuran tetap (misal 4 × 100 MB). Proses 40 MB di partisi 100 MB membuang 60 MB → internal fragmentation.

Dynamic partition: partisi mengikuti kebutuhan. Saat proses selesai, ruangnya menjadi hole.

Non-contiguous

Proses boleh dipecah

Proses 10 MB bisa dipecah jadi lima potongan 2 MB di tempat berbeda. Dua teknik: Paging dan Segmentation.

MMU (Memory Management Unit) adalah hardware yang menerjemahkan alamat virtual menjadi alamat fisik. Bahasa bayi: program bilang "aku mau alamat X", MMU menjawab "alamat X ternyata ada di RAM bagian Y".

Paging

Memori fisik dibagi menjadi frame, memori logis dibagi menjadi page, keduanya berukuran sama. Page table mencatat page mana ada di frame mana.

Logical = (Page number, Offset)

Segmentation

Paging memotong rata menurut ukuran tetap. Segmentation memotong menurut bagian logis program (code, data, stack, heap) dan ukurannya berbeda-beda. Alamat logis = (Segment number, Offset). Segment table menyimpan Base (alamat mulai, "alamat rumah") dan Limit (panjang, "ukuran rumah"). Offset harus lebih kecil dari limit.

Swapping dan virtual memory

Swapping

RAM sesak, proses dipindahkan sementara ke disk (RAM → DISK). Saat dibutuhkan kembali (DISK → RAM). Dikerjakan medium-term scheduler.

Virtual memory

"RAM-ku tidak cukup? Aku pinjam ruang dari storage." Proses yang tidak sepenuhnya muat di RAM tetap bisa berjalan.

Tambahan mentor, di luar slide

Swapping memindahkan seluruh proses. Virtual memory modern berbasis paging memindahkan per page saja, hanya saat dibutuhkan (demand paging). Ketika page yang dicari tidak ada di RAM terjadi page fault, dan OS memuatnya dari disk. Terlalu banyak page fault membuat sistem lebih sibuk memindahkan page daripada bekerja, disebut thrashing.

Latihan pemeriksa

Sepuluh jebakan UTS

Setiap baris adalah pernyataan yang terdengar benar. Tentukan dulu benar atau salah, lalu buka untuk memeriksa.

"Ready = proses menunggu I/O."
Salah. Ready menunggu CPU. Waiting yang menunggu I/O atau event.
"SJF selalu preemptive."
Salah. SJF biasa non-preemptive. Versi preemptive-nya bernama SRTF.
"FCFS bisa memotong proses yang sedang berjalan."
Salah. FCFS non-preemptive: yang sudah jalan dibiarkan selesai.
"Pada Priority, angka terbesar berarti prioritas tertinggi."
Salah menurut materi dosen. Angka terkecil = prioritas tertinggi. Tetap baca keterangan di soal.
"Round Robin memakai prioritas."
Salah. Round Robin memakai quantum time.
"Scheduler dan dispatcher itu sama."
Salah. Scheduler memilih proses. Dispatcher menyerahkan CPU ke proses terpilih (context switch, user mode, lompat ke program).
"PID menunjukkan instruksi berikutnya yang akan dijalankan."
Salah. PID = identitas proses. Instruksi berikutnya ditunjuk Program Counter.
"Page adalah bagian dari memori fisik."
Salah. Page milik memori logis. Memori fisik dibagi menjadi frame.
"Paging tidak punya fragmentasi sama sekali."
Salah. Paging tidak punya external fragmentation, tetapi masih bisa punya internal fragmentation (sisa di page terakhir).
"Alamat virtual adalah lokasi sebenarnya di RAM."
Salah. Itu alamat fisik. Alamat virtual adalah sudut pandang proses, diterjemahkan MMU menjadi alamat fisik.

Kuis kilat

Enam belas soal pilihan ganda, termasuk hitungan. Jawab, lalu baca penjelasannya. Soal yang salah menunjukkan bagian mana yang perlu dibaca ulang.

Dua puluh pertanyaan wajib, tutup catatan lalu jawab

Jawab dalam hati, baru buka jawabannya.

1. Apa itu Sistem Operasi?
Perangkat lunak sistem yang mengelola resource hardware dan software serta menyediakan antarmuka bagi pengguna.
2. Apa beda program dan proses?
Program = kumpulan instruksi pasif yang tersimpan. Proses = program yang sedang dieksekusi.
3. Apa itu kernel?
Inti OS yang berinteraksi langsung dengan hardware (proses, memori, I/O, proteksi dasar). Bukan seluruh OS.
4. Sebutkan 5 status proses.
New, Ready, Running, Waiting (Blocked), Terminated.
5. Apa beda Ready dan Waiting?
Ready menunggu CPU. Waiting menunggu I/O, event, atau resource.
6. Apa itu PCB?
Process Control Block, "KTP" proses: struktur data berisi informasi proses.
7. Sebutkan isi PCB.
Pointer, process state, PID, program counter, registers, memory limits, list of open files.
8. Apa itu context switching?
CPU menyimpan keadaan proses lama ke PCB-nya, lalu memuat keadaan proses baru dan menjalankannya.
9. Apa itu deadlock?
Dua atau lebih proses saling menunggu resource yang dipegang yang lain, sehingga tidak ada yang bisa lanjut. Penanganan: prevention, avoidance, detection, recovery.
10. Apa beda long-term, short-term, dan medium-term scheduler?
Long-term: job → ready queue (paling lambat, mengontrol degree of multiprogramming). Short-term: ready queue → CPU (paling cepat). Medium-term: swapping RAM ↔ disk.
11. Apa beda preemptive dan non-preemptive?
Preemptive: CPU boleh direbut dari proses yang berjalan. Non-preemptive: proses yang sudah dapat CPU berjalan sampai selesai atau waiting.
12. Apa itu FCFS?
First Come First Served: yang datang dulu dilayani dulu. Non-preemptive. Kelemahan: convoy effect.
13. Apa itu SJF?
Shortest Job First: burst time terkecil dulu. Non-preemptive. Menghasilkan AWT minimum.
14. Apa itu SRTF?
Shortest Remaining Time First, yaitu SJF versi preemptive: yang sisa waktunya paling kecil berjalan.
15. Apa fungsi quantum pada Round Robin?
Batas waktu maksimal sekali giliran. Jika belum selesai, proses kembali ke belakang antrean.
16. Pada Priority, angka 1 dan 5, mana yang lebih tinggi?
Angka 1 (angka lebih kecil = prioritas lebih tinggi, menurut materi).
17. Apa rumus Turnaround Time?
TT = Finish − Arrival.
18. Apa beda internal dan external fragmentation?
Internal: sisa di dalam blok yang dialokasikan. External: lubang-lubang kosong terpisah di antara blok, total cukup tetapi tidak kontigu.
19. Apa beda paging dan segmentation?
Paging: ukuran tetap (page ↔ frame), alamat (page, offset). Segmentation: menurut logika program, ukuran bervariasi, segment table berisi base dan limit.
20. Apa fungsi MMU?
Hardware yang menerjemahkan alamat virtual/logical menjadi alamat fisik.
